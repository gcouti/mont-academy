API é um balcão entre programas

Imagine que o Banco Central tem um balcão: você entrega uma ficha ("a Selic diária de jan a mar"), e recebe um papel com a resposta. Você não entra no sistema deles. Só existe o balcão, a ficha e a resposta.

ParteNo balcãoNa API do SGS
EndereçoOnde é o balcãoA URL que você chama
PedidoO que você escreve na fichaQual série, qual período
RespostaO papel que voltaOs números em JSON (para programa, não humano)
RegrasHorário, senha, limiteAutenticação e limite de chamadas

As três coisas que a turma leva

1 · A resposta é para programa ler — chaves e colchetes (JSON) não são erro, é o formato.
2 · Nem toda API é grátis nem aberta. BC é pública; WhatsApp cobra; sua corretora provavelmente não tem — daí o CSV do E06.
3 · A API pode mudar ou cair, e você não controla. Por isso cache, e por isso o dashboard mostra de quando é o número.
API é o que faz o seu sistema deixar de ser uma ilha. Onde existe API, use API; onde não existe, o importador do E06 resolve.

SGS do Banco Central, na prática

O SGS (Sistema Gerenciador de Séries Temporais) é a API JSON estável do BC: Selic, IPCA, CDI, câmbio — sem scraping nem fornecedor pago.

prompt ao agente
"Consulte a Selic atual pela API do SGS (código 4189) e exiba na home do dashboard, ao lado do PL. Cache de 1 hora — a Selic não muda a cada refresh."
Cache é obrigatório, não otimização. Sem cache, cada carregamento bate na API do BC. Com 3 abas abertas e refresh automático, são centenas de chamadas/hora para um número que muda 1×/dia → a API fica lenta, limita, e bloqueia justo quando você está mostrando para o cliente. Regra para o CLAUDE.md: toda API externa tem cache.

Alerta CVM 358

Formulário 358: administradores de companhias abertas negociando papéis da própria companhia. Público, hoje via download diário no portal de dados abertos (API prevista p/ 2027).

1
Carga diária às 6h — pendurada no mesmo fluxo n8n do E06, outra fonte.
2
Comparar com a carga anterior — o que apareceu de novo?
3
Cruzar com empresas que aparecem na posicao dos seus clientes.
4
Se cruzou, gera notificação (e-mail ou linha no dashboard).
Reaproveita o E06 inteiro: mesmo importador (outra fonte), mesmo fluxo agendado (mais um nó). É a primeira vez no curso em que construir algo novo custa quase nada — a fundação já existe.
O padrão real que se aprende aqui é detecção de mudança de estado ("o que mudou da carga de ontem para a de hoje?"). Serve para muito além da CVM: nova posição de cliente, oportunidade sem follow-up, ativo que entrou na carteira.

Fadiga de alerta

É o destino natural de todo sistema de notificação. A escada é sempre a mesma:

1. O alerta chega e você olha → 2. chega demais, você olha rápido → 3. chega demais, você arquiva sem ler → 4. o alerta importante chega, é arquivado sem ler, e o sistema virou prejuízo.
Alerta que você ignora é pior que alerta que não existe — dá a sensação de estar coberto.

Três critérios antes de criar qualquer alerta

PerguntaSe a resposta for não…
Existe uma ação que eu tomaria ao receber isso?Não é alerta, é indicador → dashboard
Quero saber disso hoje, não na revisão semanal?Não é alerta, é relatório
Se disparar 20×/semana, eu ainda leio?Aperte o filtro antes de ligar, não depois

Todo alerta nasce com filtro apertado. É mais fácil afrouxar depois do que recuperar a atenção de quem já desistiu de ler.

Separação cliente / interna. Cada gráfico e alerta declara se é visão do cliente ou visão interna. O erro real não é vazamento de sistema, é vazamento de tela: abrir o dashboard numa reunião e, na mesma tela, estar o ranking de concentração com os outros clientes. Decida duas telas (ou um modo de apresentação) agora, não na frente do cliente.
