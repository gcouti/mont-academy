Encontro 11 · Publicação, DNS e Apresentação Final

Do localhost ao seu endereço, com cadeado

A primeira vez que a aplicação sai da sua máquina. Código no GitHub, plataforma rodando 24h, e um domínio que você controla apontando para ele.

O que falta para "estar no ar"

Hoje o sistema roda quando você digita npm run dev e só vive enquanto o terminal está aberto. Fechou o notebook, morreu. Estar no ar são três coisas que ainda não existem:

1 · O código mora num lugar que não é a sua máquina (GitHub).
2 · Alguém executa esse código 24h, sem você (a plataforma).
3 · Um endereço que você controla aponta para ele (seu domínio, via DNS).

O encontro entrega as três, nessa ordem.

Prazo inegociável: registre o domínio pelo menos 5 dias antes. A propagação de DNS leva de minutos a horas e não dá para acelerar na aula. Domínio comprado no dia não fica pronto no dia. (Plano B: apresentar no endereço temporário da plataforma.)

Local e produção não são a mesma coisa

É onde quase todo projeto de iniciante quebra, e o sintoma é sempre "funciona na minha máquina".

Local — sua máquina

  • Código na pasta
  • npm run dev
  • Segredos no arquivo .env
  • Banco: Supabase de teste
  • Endereço: localhost:3000

Produção — o mundo

  • Código no GitHub
  • Plataforma roda 24h
  • Segredos nas configurações da plataforma
  • Banco: Supabase de produção
  • Endereço: https://seudominio.com.br
O que dá errado
CódigoEsquecer o push: o ar fica com a versão velha
SegredosA causa nº 1 de falha: o .env não sobe (e não deve), então a produção não tem as chaves
BancoPublicar apontando para o banco de teste, e achar que perdeu os dados
Decisão do banco: um só projeto Supabase para local e produção (recomendado agora — simples). A consequência a dizer em voz alta: teste destrutivo não se faz no banco de produção. Quando precisar testar algo que apaga, aí sim crie o segundo projeto.

Publicar: GitHub → plataforma → build

Você não configura servidor. Assina três serviços prontos: GitHub guarda o código, a plataforma executa, o registrador diz quem é dono do endereço.

O que é o build: a plataforma prepara seus arquivos para serem servidos rápido (junta, comprime, otimiza). Se falhar, a versão anterior continua no ar — build quebrado não derruba o que já estava publicado.
Aqui o branch do E04 ganha consequência: main é o que está no ar. Mexer direto em main publica o erro. Trabalhar num branch e só levar para main o que funciona deixa de ser conceito e vira proteção.

Build falhou? Mesmo protocolo do E02: ler o log → copiar → colar no agente → chamar o monitor após duas tentativas.

Variáveis de ambiente em produção

A regra do E10: segredo nunca vai no repositório (.env está no .gitignore). A consequência: a plataforma não tem as suas chaves — você cadastra à mão, uma vez, nas configurações do projeto.

VariávelDe onde vem
URL do SupabasePainel do Supabase
Chave pública (anon) do SupabasePainel do Supabase
Webhook do n8nPainel do n8n
Token do MCPGerado no E10
Sintoma clássico (a falha nº 1 do curso): o site sobe, abre, e a tela de clientes fica vazia ou dá erro de conexão. Não é o banco — são as variáveis faltando.
Chave pública ≠ chave secreta. A anon é pública e pode ir ao navegador — é o RLS do E05 que a torna segura. A service role ignora RLS e nunca vai ao navegador nem ao repositório. Confundir faz o RLS inteiro virar decoração.

Domínio, DNS e SSL

DNS — a lista de contatos da internet. seudominio.com.br é o nome; o endereço do servidor é o número.
Propagação — a resposta fica em cache (provedor, sistema, navegador). Até expirar, parte do mundo vê o endereço novo e parte vê o antigo. Não é erro, é natureza. "No celular abre e no PC não" = caches diferentes.
SSL — o cadeado do https://. A plataforma cuida automaticamente.
RegistroO que fazQuando usar
ALiga o nome a um IP fixoQuando a plataforma dá um IP
CNAMELiga o nome a outro nomeQuando dá nome.vercel.app — o caso comum (preferível)
O que o cadeado garante: o tráfego está cifrado e o domínio é de quem diz ser. O que não garante: que o site é confiável ou verdadeiro — site de golpe também tem cadeado. É o mínimo para não assustar o cliente, não desculpa para relaxar a régua do E01.
Frase-síntese do curso: você começou consultor que usa IA; termina consultor que construiu ferramenta própria. O que sai daqui não é lista de prompts — é sistema publicado no seu endereço.
