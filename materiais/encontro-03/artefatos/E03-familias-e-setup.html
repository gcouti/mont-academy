Como montar um prompt bom

Um prompt não é uma pergunta solta — é uma instrução estruturada. Quanto mais clara a estrutura, menos vezes você precisa repetir o pedido.

Anatomia de um prompt

PartePergunta que ela respondeExemplo
Papel/contextoQuem você é? Em que situação está?Você é meu assistente para revisar contratos de investimento.
TarefaO que precisa ser feito, exatamente?Resuma este contrato em até 5 bullets, destacando taxas e prazos.
Formato de saídaComo o resultado deve chegar até você?Responda em tabela markdown com colunas Cláusula / Risco / Ação.
RestriçõesO que a IA não deve fazer?Não sugira decisão de investimento, só aponte os riscos.
Exemplo (few-shot)Como seria um bom resultado?Um exemplo pronto, no formato esperado, ensina mais que uma descrição.
A ordem recomendada é contexto → tarefa → formato → restrições → exemplo. O modelo lê de cima para baixo e dá mais peso ao que vem por último — por isso o exemplo, quando existe, fica perto do fim.

Prompt fraco vs. prompt estruturado

Fraco
"Resuma esse contrato pra mim."
Sem contexto, sem formato, sem critério do que importa. O resultado varia a cada vez que você pede.
→
Estruturado
Contexto + tarefa + formato + restrição, como no exemplo abaixo. Resultado previsível, comparável entre execuções.

Exemplo completo

prompt estruturado
Contexto Você é meu assistente para revisar contratos de fundos antes de eu apresentar ao cliente. Tarefa Leia o contrato anexo e liste as cláusulas que merecem atenção: taxas, prazos de resgate, carência e multas. Formato Tabela markdown: Cláusula | Trecho | Por que importa. Restrições Não dê opinião sobre se o fundo é bom. Só aponte o que está escrito. Exemplo | Taxa de saída | "2% se resgatado antes de 12 meses" | Pode surpreender o cliente se ele precisar do dinheiro antes do prazo. → copie esta estrutura e troque o conteúdo pelo seu caso

Erros comuns

Prompt genérico demais ("me ajude com isso") produz resposta genérica demais. Quanto mais específico o pedido, mais específica — e útil — a resposta.
Pedir e não guardar o formato. Se você sempre precisa do mesmo tipo de saída, guarde o prompt pronto em vez de reescrevê-lo do zero — é a ideia que vira prompts/ deste repositório.

Quanto controle você mantém enquanto ela age

Human-in-the-loop
Propõe; você aprova cada ação antes de ela acontecer — o padrão "ler → propor → executar".
→
Human-on-the-loop
Age sozinho; você supervisiona e pode intervir. Um fluxo agendado (família 3).
→
Human-out-of-the-loop
Ninguém revisa. Nenhum uso aprovado neste curso.
"100% automatizado" é discurso de produto, não critério de trabalho. O critério não é "quanto dá para automatizar", é "quanto você pode automatizar sem deixar de responder pela decisão". Art. 17 CVM 19: automação não mitiga a sua responsabilidade.

As famílias diferem em o que fazem; este espectro, em quanto decidem sem você. Um agente de código que você deixa "resolver tudo" sem revisar o diff está deslizando para out-of-the-loop. Esta régua volta formal no E08 (revisão) e E09 ("IA transforma e sugere; o banco calcula; você decide").

MCP em 5 minutos

MCP é um protocolo aberto — o USB-C das ferramentas de IA. Antes, cada integração era um cabo proprietário; com um padrão, a mesma ferramenta (Gmail, Drive, banco, sistema da Mont) serve a qualquer cliente que fale o protocolo.

PapelO que éNo curso
Servidor MCPQuem expõe ferramentasVocê constrói um no E10
Cliente MCPQuem consome (Claude Code, chat c/ conectores)Usado desde hoje
FerramentaAção nomeada, com entrada e saídacriar_tarefa no E10
Uma ferramenta tem nome, descrição (o que o modelo lê para decidir se usa), entrada e saída. A descrição é a parte subestimada: ferramenta mal descrita não é chamada. O MCP da Mont aparece no E05.
